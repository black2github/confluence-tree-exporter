# Выгрузка дерева страниц Confluence в Markdown (offline-поставка)

Автономный пакет для **закрытого контура без доступа в интернет**. Выгружает
дерево (или отдельную страницу) Confluence в набор `.md`-файлов с frontmatter,
сохраняя иерархию «файл рядом с папкой» и разрешая внутренние ссылки.

Все зависимости приложены готовыми колёсами (`wheels/`).

**Сверка версий между контурами.** При старте каждая утилита (выгрузка и
critic) печатает строку вида
`confluence-tree-exporter: версия 1.1.0, отпечаток исходников 507883e2`.
Номер поднимается при каждой сборке пакета; отпечаток считается автоматически
по составу всех исходников — **любое** изменение любого файла его меняет,
даже если номер поднять забыли. Одинаковая версия на внутреннем и внешнем
контуре = совпадают и номер, и отпечаток.

Важно понимать, что это не коммерческий продукт, а набор скриптов для создания подручного средства/инструмента.
В нем почти наверняка есть ошибки, но, скорее всего, не критичные (не тормозящие конвертацию). 
На что обратить особое внимание: 

- на случаи описания требований внутри макросов. Далеко не все из них полностью или корректно обрабатываются. 
Если в вашем сервисе именно такая ситуация - сообщайте,подумаем, что можно сделать в ограниченные сроки пилота.
- на информацию по разметке цветом, когда одна цветовая разметка вложена в другую (см. отчет migration-colors-report.md после конвертации с ключем --tasks).

## Требования на целевой машине

- **Windows x64**
- **Python 3.12 (x64)** — установлен и доступен как `py -3.12` или `python`.
- **Сетевой доступ к самому Confluence** (интернет не нужен, но до
сервера Confluence машина достучаться должна — иначе выгружать нечего).

## Установка

1. Распакуйте архив в любой каталог, например `C:\confluence-tree-exporter\`.
2. Запустите в **PowerShell** установку (создаст `.venv` и поставит зависимости из `wheels\`):
  ```
   install.bat
  ```
3. Настройте доступ к Confluence — скопируйте пример и заполните значения:
  ```
   copy .env.example .env
   notepad .env
  ```
   Обязательные поля: `CONFLUENCE_BASE_URL`, `CONFLUENCE_USER`, `CONFLUENCE_PASSWORD`.

## Запуск

### Выгрузка целого дерева

```
run-tree.bat <page_id> <service_code> <subdir> [source] [флаги]
```

- `page_id` — ID корневой страницы поддерева в Confluence.
- `service_code` — код сервиса (влияет на путь и на `doc_id` в frontmatter), например `CORP_CARDS`.
- `subdir` — подкаталог внутри вывода, например `лимиты`.
- `source` — необязательный тег источника (по умолчанию `DBOCORPESPLN`).

Пример:

```
run-tree.bat 291472147 CORP_CARDS лимиты --tasks --http --with-images
```

Результат появится в:

```
conf-requirements\<service-code>\<subdir>\...
```

(рядом с `.bat`-файлами; `<service-code>` — код в нижнем регистре, `_`→`-`).

### Выгрузка одной страницы (или нескольких по запятой)

```
run-page.bat <page_id[,page_id2,...]> <service_code> <subdir> [source] [флаги]
```

## Флаги (для обоих сценариев)


| Флаг                            | Действие                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--http`                        | Прямой HTTP-доступ (как браузер), в обход REST API. Помогает, если REST API закрыт (**ситуация на внутреннем контуре на 07.2026**).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `--all`                         | Выгружать ВСЁ содержимое, включая неподтверждённые (цветные) фрагменты. По умолчанию — только подтверждённые «чёрные».                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `--tasks`                       | Выгружать ВСЁ содержимое с разметкой **CriticMarkup** — цветные фрагменты оборачиваются в маркеры задач `{++ID: …++}`/`{--ID: …--}` (см. раздел ниже). Взаимоисключающий с `--all`. Дополнительно пишет `migration-manifest.yaml` и отчёт по цветам.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `--keep-history`                | Сохранять таблицу «История изменений» (по умолчанию она вырезается).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `--with-images`                 | Скачивать картинки/образы... в подкаталог `img/` рядом с `.md`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `--with-attachments`            | Скачать файлы на странице в подкаталог `files/` рядом с `.md`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `--with-index`                  | Генерировать навигационные `index.md` по папкам (для статических генераторов сайтов, используемых для GitLab и т.д.). Только для `run-tree.bat`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `--drop-strikethrough`          | Исключать зачёркнутый текст. В режимах approved/`--all` — любой; в режиме `--tasks` — **только чёрный** (применённый мусор ПРОМ): цветное зачёркнутое — удаление задачей, оно всегда сохраняется маркерами `{--ID: …--}`, иначе `reject-all` не смог бы восстановить ПРОМ-состав.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `--unapproved-jira <file.json>` | Список Jira ID **неутверждённых** задач (эмуляция похода в RAG): если джира из **чёрной** строки «Истории изменений» входит в список — состав страницы считается неутверждённым (случай новой страницы, где всё «чёрное» с рождения). Реакция по режиму: с `--tasks` весь чёрный контент оборачивается вставками `{++ID: …++}` (reject-all даст пустую страницу, apply примет состав целиком), задача попадает в манифест с `confidence: forced`, frontmatter `status: draft`; без `--all`/`--tasks` страница пропускается с предупреждением; с `--all` — контент полный, но `status: draft`. Формат файла: `["GBO-1", "DBOCORPESPLN-123456"]` или `{"unapproved_jira": [...]}`. Ограничение: fenced-код-блоки маркерами не помечаются (предупреждение в логе). Без ключа поведение не меняется. |




Пример с флагами:

```
run-tree.bat 291472147 CORP_CARDS лимиты --http --with-images --all
```

## Миграция статуса требований (CriticMarkup)

Помимо режимов «только подтверждённые» и `--all`, пакет умеет выгружать требования
с сохранением **статуса задач** в разметке CriticMarkup: цвет фрагмента (задача Jira из
таблицы «История изменений») превращается в маркер `{++ID: …++}` (добавлено), `{--ID: …--}`
(удалено) или служебный столбец `status` в таблицах.

Выгрузка с маркерами:

```
run-tree.bat 291472147 CORP_CARDS лимиты --tasks --http --with-images
```

Кроме `.md` с маркерами создаются:

- `migration-manifest.yaml` — реестр мигрировавших задач (с `first_seen` — датой первой записи истории);
- `migration-colors-report.md` / `.json` — отчет по цветам, включая те, что без задачи (`UNKNOWN-*`), коллизии,
уплощённые вложенности, сводка цветов с ΔE (для калибровки "черного") — вход для ручного разбора;
- `migration-apply-order.md` — предложение ПОРЯДКА вливания задач на внешнем контуре
(по дате первой записи «Истории изменений»; задачи одного дня помечены, задачи без
даты — отдельной секцией) + готовый блок команд `apply`.

В отчёте каждый цвет показан в двух формах: **«Цвет в HTML»** (`rgb(255,102,0)`) — та,
в которой он записан на странице Confluence, по ней фрагмент ищется поиском в исходнике;
и канонический `#rrggbb` — для сверки с набором `black_colors`. Уплощения делятся по
`confidence`: `high` (структурная вложенность цветов), `medium` (зачёркнутый фрагмент
вплотную к правке другой задачи — приоритетная очередь проверки), `post-pass`.

Дальнейшая работа с маркерами — утилитой **critic** на внешнем контуре (работает с локальными `.md`, Confluence
не нужен):

```
run-critic.bat apply GBO-12345 --path conf-requirements\   REM принять правки задачи (вышла на ПРОМ)
run-critic.bat reject GBO-12345 --path conf-requirements\  REM откатить правки задачи
run-critic.bat apply-all --path conf-requirements\         REM целевое состояние (все задачи приняты)
run-critic.bat reject-all --path conf-requirements\        REM текущий ПРОМ (все правки убраны)
run-critic.bat lint --path conf-requirements\
run-critic.bat list --path conf-requirements\              REM список незавершённых задач
```

Команды правки редактируют `.md` **на месте** (модель работы под git: diff/ревью/откат).
Подробное руководство: `app\scripts\CI\critic_manual.md`.

**Автоматическое восстановление истории (этап 4 роадмапа)** — `run-history.bat`:
позадачное вливание хронологии в git-репозиторий. На каждую задачу списка:
свежая копия архива → `apply` всех принятых задач → `reject-all` →
`git commit` + `git tag src/<JIRA-ID>`. Порядок задач берётся из файла —
подходит как есть блок команд из отчёта `migration-apply-order.md`
(формируется прогоном `--tasks`).

```
run-history.bat <каталог-архива> <корень-git-репозитория> <файл-списка-задач> [--dry-run] [--push]
```

Пример (сначала посмотреть план без изменений, затем выполнить):

```
run-history.bat C:\src-cc\sources\raw C:\src-cc apply-order.txt --dry-run
run-history.bat C:\src-cc\sources\raw C:\src-cc apply-order.txt
```

где `apply-order.txt` — список задач по порядку: скопируйте блок команд из
`migration-apply-order.md` (подходит как есть) или перечислите JIRA-ID построчно.
Срезы лягут в `C:\src-cc\sources\confluence` коммитами с тегами `src/<JIRA-ID>`.
Требования: git настроен (user.name/email), рабочее дерево репозитория чистое.
Предохранители: существующий тег среза, грязное дерево, ошибка critic/git —
остановка без порчи истории. Push — только с явным `--push`.
Полный список опций — в шапке `run-history.bat`.

## Починка уже выгруженных деревьев

Правки экспортёра действуют начиная с ОЧЕРЕДНОЙ выгрузки — деревья, выгруженные
раньше, остаются как есть. `run-repair.bat` лечит их на месте: доступ к Confluence
не нужен, поэтому чинить можно и во внутреннем контуре сразу после выгрузки, и во
внешнем после переноса файлов. Все починки идемпотентны — повторный запуск ничего
не портит.

```
run-repair.bat conf-requirements\ --unfold --flatten-nested --unfence-html --name-status-column --dry-run
run-repair.bat conf-requirements\ --unfold --flatten-nested --unfence-html --name-status-column
```

Сначала `--dry-run` и просмотр списка, затем тот же запуск без него. Это же
сочетание ключей — рецепт для выгрузок, снятых предыдущими версиями пакета:
после него `reject-all` снимает всю неутверждённую разметку за один заход.


| Ключ                            | Что чинит                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--unfold`                      | Свёрнутые значения frontmatter. PyYAML переносил длинное значение на вторую строку (для кириллицы это ~150 байт), и всё, что читает файл построчно — `grep`, инвентаризация выгрузки, — видело обрезанный `title` с незакрытой кавычкой; разные страницы выглядели дублями.                                                                                                                                                                                                                                                                                                                                                                                        |
| `--flatten-nested`              | Литеральную вложенность маркеров: `{++A: … {++B: …++} …++}`. Возникает, когда блочный маркер накрывает участок с врезками соседних задач. Нотация вложенность запрещает, поэтому `apply`/`reject` на таком файле падают с «литеральная вложенность маркеров запрещена» и обрывают весь прогон. Уплощение выносит внутренние маркеры наружу, текст внешнего остаётся за его задачей.                                                                                                                                                                                                                                                                                |
| `--unfence-html`                | Ограждения кода ``` внутри HTML-таблиц: заменяет их на `<pre>`. Как код такое не отображается нигде, а `apply`/`reject` считают всё между ограждениями кодом и переносят байт-в-байт — поэтому маркеры внутри они не видят, и неутверждённые требования молча остаются в «чистом ПРОМ». Для примера: на дереве сервиса "Корпоративные карты" из 614 страниц так пряталось 204 фрагмента разметки в 8 файлах (риск получить в ПРОМ-срезе фрагменты примеров запросов/ответов, не имеющих к нему отношения. Не фатально, но неприятно.) Меняются только ограничители, содержимое остаётся как было; если ограждения в таблице не сходятся в пары, файл не трогается. |
| `--name-status-column`          | Даёт имя служебному столбцу `status` в таблицах, где он остался безымянным. Нотация опознаёт табличную правку по имени столбца, а выгрузка Confluence держит заголовки внутри `<tbody>` — столбец оставался пустым, и `apply`/`reject` пропускали такую таблицу целиком: разметка `+JIRA-ID` доезжала до ПРОМ-среза, а строки, помеченные на удаление, не удалялись. Пустая ячейка шапки получает имя; если размечена сама шапка — над ней добавляется строка-шапка, маркер не теряется. Ячейку шапки, занятую текстом, не трогает. |
| `--flag-page <JIRA-ID>`         | Ставит страничный флаг `unapproved_jira` на ВСЕ страницы указанного пути. Для замороженного поддерева: требования не отменены, а отложены — в git они лежат целиком, но в ПРОМ-срез не попадают, а `apply <JIRA-ID>` возвращает их разом. Ключ `--unapproved-jira` здесь бессилен: он берёт задачу из маркеров в теле, а у таких страниц маркеров нет вовсе (нет таблицы «История изменений» → нет карты «цвет → задача», весь текст считается чёрным). Страница с флагом другой задачи не перезаписывается. Задача обязана встречаться маркером в обрабатываемом пути либо быть в `migration-manifest.yaml` — иначе прогон откажется работать: флага задачи, которой нет в дереве, не видит `critic list`, и страница осталась бы пустой навсегда. |
| `--unapproved-jira <file.json>` | Проставляет страничный флаг `unapproved_jira` там, где весь состав страницы принадлежит неутверждённой задаче (формат списка — как у `--unapproved-jira` в `run-tree.bat`). После этого `reject` очищает такую страницу целиком, включая блоки кода из макросов, которые маркерами не помечаются.                                                                                                                                                                                                                                                                                                                                                                  |


Обратите внимание: путь задаётся как каталог, и корневая страница поддерева — файл РЯДОМ с каталогом, а не внутри него. Её нужно указать отдельным запуском:

```
run-repair.bat <папка-поддерева> --flag-page GBO-52119
run-repair.bat <страница-поддерева>.md --flag-page GBO-52119
```

Безопасность: после каждой правки frontmatter сверяется по смыслу (`yaml.safe_load`
до и после), а уплощение — по тексту без разметки. Если правка изменила бы данные,
файл не пишется, а строка уходит в отчёт. Несходящаяся разметка (незакрытый маркер,
лишний закрыватель) не трогается — такие места показывает `run-critic.bat lint`.

Найти места, требующие починки, до её запуска:

```
run-critic.bat lint --path conf-requirements\
```

Линтер перечислит все случаи вложенности сразу — в отличие от `apply`/`reject`,
которые останавливаются на первом же файле.

## Возможные проблемы

- **Ошибка сертификата / не проходит коннект.** Если Confluence за самоподписанным
сертификатом (ситуация на 07.2026), откройте `app\confluence_loader.py` и замените `verify_ssl=True`
на `verify_ssl=False`.
- **REST API закрыт.** Добавьте флаг `--http` (или `CONFLUENCE_USE_HTTP=true` в `.env`).
- `install.bat` **не находит Python.** Проверьте `py -3.12 --version`. Нужен именно
Python 3.12 x64 (колёса собраны под эту версию и платформу).

## Что внутри

```
confluence-tree-exporter  
├─ app\                 исходники (только модули, нужные для выгрузки)
│  ├─ data\             справочники (services.json, page_exclusion_rules.json и др.)
│  ├─ color_map.py      карта «цвет→задача» из истории изменений (для --tasks)
│  ├─ scripts\CI\       утилита critic (работа с CriticMarkup) + critic_manual.md
│  └─ scripts\repair_export.py  починка уже выгруженных деревьев
├─ wheels\              колёса всех зависимостей (cp312 / win_amd64)
├─ requirements.txt     список зависимостей (версии закреплены)
├─ .env.example         шаблон настроек доступа
├─ install.bat          установка (venv + offline pip)
├─ run-tree.bat         выгрузка дерева
├─ run-page.bat         выгрузка страницы
├─ run-critic.bat       работа со статусом требований (CriticMarkup)
├─ run-history.bat      восстановление истории в git по задачам (этап 4 роадмапа)
├─ run-repair.bat       починка уже выгруженных деревьев (frontmatter, вложенность, ограждения)
└─ README.md            этот файл
```
