# critic.py — руководство пользователя
#
# All rights violated - пользуйтесь на здоровье и заходите к аналитикам ДРЦС, если что.

Инструмент работы со статусом требований аналитики в разметке **CriticMarkup** и не только: снятие/откат правок
по конкретной задаче Jira, проверка разметки и отчёт о незавершённых задачах. 
Поддерживается как чистый markdown, так и разметка тегами внутри сырого HTML блока. 

Запуск:

```
python app/scripts/CI/critic.py <команда> [аргументы] [ключи]
```

---

## Общая модель: откуда читаются данные и куда пишется результат

- **`--path`** во всех командах — это **вход**: путь к `.md` для обработки.
  - файл → обрабатывается он один;
  - каталог → рекурсивный обход всех `*.md` внутри;
  - по умолчанию `--path .` (текущий каталог).
- Команды правки (`apply`, `reject`, `apply-all`, `reject-all`) **редактируют файлы на месте
  (in-place)** — результат записывается обратно в те же `.md`. Отдельного каталога-приёмника
  нет. Модель — «редактирование рабочей копии docs-репозитория под git»: результат виден как
  `git diff`, ревьюится в MR, откатывается через git.
- Команды `lint` и `list` **ничего не пишут в файлы** — только печатают результат в вывод.

Гарантии команд правки:
- файл, который после операции не изменился, **не перезаписывается** (идемпотентность, чистый
  `git status`);
- переводы строк (CRLF/LF) и кодировка сохраняются **байт-в-байт**;
- при неоднозначности (вложенный или незакрытый маркер) процесс **прерывается** с ненулевым
  кодом возврата и указанием «файл:строка», файл при этом не портится.

**Формат `<TASK-ID>`** — идентификатор задачи Jira (`GBO-12345`, `TEAMTB-3633`) либо
плейсхолдер `UNKNOWN-<hex>`. Не подходящий под маску id команда отклоняет.

## Команды правки

### `apply <TASK-ID>` — принять правки задачи (задача вышла в ПРОМ)

Разворачивает маркеры указанной задачи в финальный текст: вставки `{++ID: …++}` остаются
текстом, удаления `{--ID: …--}` убираются, замены `{~~ID: старое~>новое~~}` заменяются на
новое. Маркеры **других** задач не трогаются. Служебный столбец `status` таблиц: строки со
значением `+ID` очищаются, со значением `-ID` — удаляются целиком; если после этого столбец
пуст, он убирается.

Ключи:
- `--path` — файл/каталог (см. общую модель); правит на месте;
- `--dry-run` — показать, какие файлы и сколько правок изменились бы, **ничего не записывая**;
- `--status-column` — имя служебного столбца таблиц (по умолчанию `status`).

```
python app/scripts/CI/critic.py apply GBO-12345 --path docs/
python app/scripts/CI/critic.py apply GBO-12345 --path docs/ --dry-run
```

### `reject <TASK-ID>` — откатить правки задачи (задача отменена)

Обратная операция: вставки задачи убираются, удаления возвращаются на место, замены
откатываются к старому значению. `status`: `+ID` → строка удаляется, `-ID` → очищается.
Маркеры других задач не трогаются.

Ключи: `--path`, `--dry-run`, `--status-column` (как у `apply`).

```
python app/scripts/CI/critic.py reject GBO-12345 --path docs/
```

### `apply-all` — принять правки ВСЕХ задач (целевое состояние)

Разворачивает маркеры всех задач сразу — получается документ «как будет, когда всё выйдет в
ПРОМ». Правит на месте!!!

Ключи: `--path`, `--status-column`. (Флага `--dry-run` пока нет — чтобы посмотреть без изменений,
сделайте это на копии каталога.)

```
python app/scripts/CI/critic.py apply-all --path docs/
```

### `reject-all` — откатить правки ВСЕХ задач (текущий ПРОМ)

Убирает все правки — получается документ «как сейчас на ПРОМ». Правит на месте!!!

Ключи: `--path`, `--status-column`.

```
python app/scripts/CI/critic.py reject-all --path docs/
```

> Чтобы получить целевое/ПРОМ-состояние **не трогая исходники** — сначала скопируйте каталог и
> укажите `--path` на копию.

## Проверка и отчёт (файлы не изменяются)

### `lint` — проверить корректность разметки

Проверяет разметку по правилам (вложенные/незакрытые маркеры, маркер без корректного id,
плейсхолдеры `UNKNOWN-*`, маркер, разрывающий конструкцию или попавший в fenced-блок/смарт-
ссылку/сырой HTML, удаляемый текст внутри чужой вставки и др.). Печатает находки в виде
`файл:строка: [error|warning] КОД: сообщение`.
Целевое назначение - часть линтера при вливании требований в Git (защита от вливания в main незавершенных задач).

**Код возврата:** `1`, если есть хотя бы одна ошибка (`error`) — так «плохой» MR не сливается;
`0`, если ошибок нет (одни предупреждения `warning` слияние не блокируют).

Ключи:
- `--path` — файл/каталог;
- `--format text|json` — человекочитаемый вывод (по умолчанию) или JSON для аннотаций CI.

```
python app/scripts/CI/critic.py lint --path docs/
python app/scripts/CI/critic.py lint --path docs/ --format json
```

### `list` — список незавершённых задач в репозитории (чтобы не искать по Jira закрытого контура)

Обходит `.md` и собирает все задачи, у которых ещё есть маркеры (из inline-маркеров,
столбца `status`, HTML-нотации), с перечнем файлов и строк. Содержимое fenced-блоков
игнорируется.

Ключи:
- `--path` — файл/каталог;
- `--format text|md|json` — формат вывода;
- `--manifest <migration-manifest.yaml>` — сверить с реестром миграции: разделить задачи на
  **мигрировавшие** (есть в манифесте) и **новые**, показать остаток переходного периода
  (сколько мигрировавших задач ещё имеют маркеры и сколько уже снято на ПРОМ).

**Код возврата:** всегда `0` (информационная команда).

```
python app/scripts/CI/critic.py list --path docs/
python app/scripts/CI/critic.py list --path docs/ --manifest docs/migration-manifest.yaml
```

## Коды возврата — сводка

| Команда | 0 | 1 | 2 |
|---|---|---|---|
| `apply` / `reject` / `apply-all` / `reject-all` | успех | — | неоднозначность (вложенный/незакрытый маркер), путь не найден |
| `lint` | ошибок нет | есть ошибки | путь не найден |
| `list` | всегда | — | путь не найден |
